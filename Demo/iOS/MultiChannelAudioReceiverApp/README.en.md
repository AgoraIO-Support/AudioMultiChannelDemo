# iOS Multi-Channel Audio Receiver Demo (MultiChannelAudioReceiverApp)

A **pure receiver** verification app built on the Agora Native SDK for iOS
(`AgoraRtcEngine_iOS` 4.7.0, integrated via CocoaPods; the Xcode project is generated by
XcodeGen). It joins a channel as **audience**, receives a remote host's multi-channel
(OPUSMC, payload types 123/124/125, 48 kHz, 3~8 channels) or normal stereo/mono audio
stream, and lets the tester **select which channels to hear and set per-channel volume**
through Native SDK private parameters. See `Spec/native_sdk_audio_multichannel_spec.md`
for the requirements baseline.

This app is a port of the macOS receiver (`Demo/macOS/MultiChannelAudioReceiver`) with
feature parity; the UI adapts the macOS "control | monitor" two-column layout to a
**stacked, scrollable layout** for iPhone portrait (see "Differences from the macOS app").

> Companion senders: `Demo/macOS/MultiChannelAudioSender/` (macOS broadcaster publishing
> bundled multi-channel WAV assets), or `sample_send_wav_multiopus` in `Demo/linux`.

## UI Language

The UI is bilingual (**English / 中文**) and defaults to English. Switch it with the
Language picker at the top of the main view — control labels re-render immediately, while
status-bar text generated at event time refreshes on the next status update —
and the choice is persisted via `@AppStorage("uiLanguage")` across launches. The strings
live in `MultiChannelAudioReceiverApp/L10n.swift` (lookup table + String(format:)
interpolation); log and status lines are emitted in the language active at the time
(already-appended log lines keep their original language).

## Features

- **Receive-only**: joins in `.liveBroadcasting` profile with the audience role;
  microphone/camera are never published; auto-subscribes remote audio and video.
- **Layout**: the language bar and the Join section are pinned at the top; the scrollable
  middle holds "Remote Multi-Channel Control" (top) and the "Monitor — UID xxx" section
  (bottom); the log area is fixed at 160 pt at the bottom.
- **Remote video display (on demand)**: when the selected host publishes video, the monitor
  section renders the picture (`UIViewRepresentable` wrapping a `UIView` +
  `setupRemoteVideo`, renderMode = fit, aspect driven by the stream's real dimensions from
  `remoteVideoStats`, defaulting to 16:9); audio-only hosts show just the bitrate chart
  plus an "Audio only" note.
- **Receive bitrate charts**: the selected remote user gets separate audio and video receive
  bitrate sparklines with Y-axis labels (max/0) — audio in green, video in blue, each covering
  the last 60 `remoteAudioStats`/`remoteVideoStats` samples (~2-minute window); the video
  chart only appears while the host publishes video.
- **Remote user list**: driven by remote audio **or video** publish state — uids are added in the
  `remoteAudioStateChangedOfUid` / `remoteVideoStateChangedOfUid` callbacks when media is
  starting/decoding and removed on `didOfflineOfUid`, so **only hosts actually publishing
  media are listed; audience-role clients never appear**. All three host shapes are covered:
  audio+video, audio-only, and video-only (selecting a video-only host shows a "Video only"
  note in the control section and sends no volume parameters).
- **Channel-count selector (1~8, default 8)**: a **pure display filter** — it only decides
  how many channel rows are rendered and changes nothing you hear. It exists because the
  Native SDK receiver has no callback reporting the remote stream's actual channel count,
  so you align the UI with the sender's material manually: choose 2 for a normal stereo
  stream (only channel 1/2 rows), keep 8 for an 8-channel stream, 3/5/7 accordingly. Two
  caveats: with no remote user selected, switching it has no visible effect (channel rows
  are not rendered then); hidden channels keep their volume state (all enabled at 100 by
  default), so choosing 2 does NOT mute channels 3~8 of an 8-channel stream — use a row's
  toggle to mute.
- **Per-channel control**: each row has an enable toggle and a 0~100% volume slider,
  applied immediately through the `che.audio.neteq.adjust_decoded_volume` private
  parameter. All channels default to enabled at 100.
- **Audio frame dump**: `che.audio.frame_dump` toggle. **Verified on iOS (2026-10-13,
  iPhone 16 Pro simulator, iOS 18.3, SDK 4.7.0): dumps land in the app container's
  `Library/Caches/`** — the smoke test (no remote host in channel) produced
  `audio_dump_play_0.wav` (playout) and `audio_dump_playback_mixer_0.wav` (mixer); the
  per-remote-user decoded-output file `audio_dump_playback_before_mixed_0_<timestamp>_<uid>.wav`
  naming **still needs verification in a real multi-channel channel** (see the macOS README
  for the full macOS naming rules — they are not assumed to carry over).
  Dumps do not land in Documents/ (UIFileSharingEnabled does not help here). Retrieval:
  - Simulator: `xcrun simctl get_app_container booted com.agora.demo.MultiChannelAudioReceiverApp data`
    prints the container path directly;
  - Device: Xcode → Window → Devices and Simulators → select the device → Installed Apps →
    this app → gear menu → Download Container, then inspect `AppData/Library/Caches/`.
- **Log area**: scrolling log at the bottom covering join/leave, remote user events,
  connection state changes and SDK errors (capped at 1000 lines, mirrored unbuffered to stdout).

## Prerequisites

- iOS 14.0+ (app target deployment target 14.0 — rationale below), Xcode 14+
  (verified with Xcode 16.2)
- CocoaPods (`pod` on PATH) and XcodeGen (`xcodegen` on PATH)

> **Deployment target rationale**: the project was planned with an iOS 13.0 floor (the
> Podfile keeps `platform :ios, '13.0'` as the Pods compile floor), but the app itself uses
> the SwiftUI lifecycle (`@main App`), `@AppStorage`, `GroupBox` and `onChange(of:)`, all of
> which require iOS 14+, so the app target's deployment target is **14.0**.

## Build

The `MultiChannelAudioReceiverApp.xcodeproj` is generated by XcodeGen from `project.yml`
and is not committed; CocoaPods requires the xcodeproj to exist, so the order is fixed:

```bash
cd Demo/iOS/MultiChannelAudioReceiverApp
xcodegen           # generates MultiChannelAudioReceiverApp.xcodeproj from project.yml
pod install        # integrates AgoraRtcEngine_iOS 4.7.0, creates MultiChannelAudioReceiverApp.xcworkspace
open MultiChannelAudioReceiverApp.xcworkspace   # open the workspace in Xcode (NOT the xcodeproj)
```

Command-line build (simulator, no certificate needed):

```bash
xcodebuild -workspace MultiChannelAudioReceiverApp.xcworkspace \
    -scheme MultiChannelAudioReceiverApp -configuration Debug \
    -destination 'generic/platform=iOS Simulator' \
    CODE_SIGNING_ALLOWED=NO build
```

## Code signing (important)

- The project defaults to `CODE_SIGNING_ALLOWED=NO` (simulator/CI builds, no developer
  certificate required).
- **Agora's prebuilt dynamic frameworks ship their simulator slices unsigned**, and the
  arm64 simulator on Apple Silicon refuses to load unsigned dylibs; these frameworks are
  linked weak, so a load failure does not crash — it surfaces at runtime as
  `NSClassFromString("AgoraRtcEngineKit") == nil` and `sharedEngine` returning nil
  (engine creation fails). To handle this, the Podfile's `post_install` hook ad-hoc signs
  every vendored `.framework` under `Pods/` (`codesign --sign -`); the signature survives
  embedding into the app. Device builds with a real signature are unaffected — the Embed
  phase re-signs the frameworks with the developer certificate.
- **Running on a device**: assign a valid development team in the target's Signing settings
  (and drop the `CODE_SIGNING_ALLOWED=NO` override); otherwise the app cannot be installed.

## Usage

1. **Start a multi-channel sender** (e.g. the 8-channel WAV sender in Demo/linux):

   ```bash
   cd Demo/linux/out
   ./sample_send_wav_multiopus --channelId <channel> --token <token> \
       --audioFile "public/8_Channel_ID_signed_16_bit_pcm.wav" \
       --numOfChannels 8 --custom_channel_num 8 --custom_payload_type 125 --sampleRate 48000
   ```

2. **Join the same channel from this app**: the App ID is pre-filled with the default
   `43f818097c124394821bd44598b7ca9d` (your edits are persisted via `@AppStorage` across
   launches); fill in Token (leave empty for projects without an App Certificate),
   Channel ID and UID (0 = auto-assign), then tap "Join". The status line shows the
   connection state plus the assigned local UID.
3. **Select the remote user**: pick the sender's uid in the "Remote Multi-Channel Control"
   section (the first remote is auto-selected). The current state of all 8 channel rows is
   pushed to that uid immediately upon selection.
4. **Listen per channel**: mute/enable a channel with its toggle, or drag its slider to
   set the volume percentage. When the sender plays the Channel ID sample (each channel
   carries distinguishable content), check channels one by one for cross-talk.
5. For a normal stereo stream, set "Channels" to 2 so only channel 1/2 rows appear (a pure
   display filter that does not change what you hear; if channels 3~8 are still audible,
   that is because hidden rows stay enabled at their default 100% — mute them explicitly
   with their toggles if needed).

## Private parameters

### Per-channel decoded volume `che.audio.neteq.adjust_decoded_volume`

```json
{"che.audio.neteq.adjust_decoded_volume":{"remoteUid": 109016691, "index": 1, "volume": 100}}
```

- `remoteUid`: target remote user uid;
- `index`: **1-based** channel index (1~8);
- `volume`: 0~100, a percentage. `100` = full volume (audible), `0` = muted.
- "Selecting channels to hear" = set chosen channels to 100 and the rest to 0.

### Audio frame dump `che.audio.frame_dump`

```json
{"che.audio.frame_dump":true}
```

When enabled, the SDK writes decoded audio frames to disk for offline channel-content
verification. The iOS dump location is described in "Features" above
(**sandbox `Library/Caches/`, verified on the simulator; per-remote-user file naming still
to be verified**).

## Command-line automation (for regression testing)

Launch arguments (mapped into the `UserDefaults` argument domain) are identical to the
macOS app: `-autoChannel` / `-autoJoin` / `-autoDump` / `-autoQuitAfter`. The app log is
also mirrored to stdout unbuffered.

Passing arguments and collecting logs on the iOS simulator:

```bash
xcrun simctl install booted <path>/MultiChannelAudioReceiverApp.app
xcrun simctl launch --console booted com.agora.demo.MultiChannelAudioReceiverApp \
    -autoChannel <channel> -autoJoin YES -autoDump YES -autoQuitAfter 120
# --console attaches the app's stdout/stderr to the current terminal
# (the counterpart of running the macOS binary directly)
```

- `autoJoin`: join as audience on launch (uid 0 = auto-assign); `autoDump`: enable
  `che.audio.frame_dump` at join; `autoQuitAfter`: seconds until the app terminates
  itself (> 0) — **iOS has no public "terminate app" API, so this is implemented as
  `exit(0)`** (the macOS app uses `NSApplication.terminate`).
- A physical device cannot take launch arguments from the command line (use the Xcode
  scheme's Arguments, or drive the UI manually).
- Smoke-verified 2026-10-13 on an iPhone 16 Pro simulator (iOS 18.3): auto-join over the
  real Agora network succeeded (audience role), the dump parameter was applied (returned 0),
  and the app quit itself on schedule.

## Notes

- **No multi-channel parameter is needed on the receiver**: the Native SDK decodes OPUSMC
  multi-channel streams adaptively under the 123/124/125 negotiation mechanism (including
  odd channel counts 3/5/7), and receives normal stereo/mono streams without any special
  handling. Payload type / `custom_channel_num` parameters are only required on the
  **sender** side (see `Demo/linux/README.md`).
  **Caveat: the 3/5/7 adaptive-decoding conclusion comes from macOS / Linux testing
  (see `Docs/audio_multichannel_test_summary.md` §4.1). Web→iOS testing has covered 4/6/8
  channels, but an intermittent 1-channel issue remains open; 3/5/7 still need separate
  iOS verification (see §3 and §5.1 of the summary).** What has been verified on the iOS simulator: engine creation,
  audience join, auto-subscribe, and frame-dump file creation (2026-10-13).
- **The channel-count selector only controls the UI rows**: switching it pushes no SDK
  parameter; setting an `index` beyond the stream's actual channel count has no effect in
  the SDK; whenever the selected uid changes, the state of all 8 rows (including hidden
  ones) is re-applied so behavior stays deterministic.
- **The volume parameter acts after decoding, before playout**: it only affects what this
  client hears, not what other participants in the channel hear.
- On iOS the `AVAudioSession` is managed by the Agora SDK itself; the app does no audio
  session configuration. The audience role publishes no audio track, so the app requests no
  microphone/camera permission (no corresponding UsageDescription keys in Info.plist).
  `UIBackgroundModes = audio` is declared so channel audio keeps playing in the background.
- The iOS 4.7.0 SDK headers (`AgoraRtcEngineDelegate.h`) were checked and — like macOS —
  expose only `didOccurError` (no `didOccurWarning`); the log area reports `didOccurError`
  plus connection state changes.

## Differences from the macOS app

- **Layout**: the two-column "control | monitor" layout becomes a stacked, scrollable
  middle area (control above, monitor below) to fit iPhone portrait width; the Join
  section's status/local-UID text sits on its own row to avoid narrow-screen crowding.
- **The log area does not support text selection**: `.textSelection` requires iOS 15+ while
  this project targets iOS 14.0; logs can be collected via the stdout mirror
  (`simctl launch --console` or the Xcode console).
- The per-channel volume percentage label uses a monospaced font
  (`.font(.system(.body, design: .monospaced))`) instead of `.monospacedDigit()`
  (the latter requires iOS 15+).
- `autoQuitAfter` is implemented as `exit(0)` (macOS uses `NSApplication.terminate`).
- The app entry point drops the macOS minimum window size constraint
  (`.frame(minWidth:minHeight:)`).
- Dump location differs: iOS uses the sandbox `Library/Caches/` (simulator-verified),
  macOS uses `~/Library/Logs/`.
